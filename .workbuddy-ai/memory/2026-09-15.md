# 2026-09-15

## Built PolicyPulse (hackathon app, theme "Earth Forward")

Full build from an empty directory. Next.js 15 App Router + React 19 + TypeScript strict,
Tailwind 3.4 with CSS-variable design tokens, Recharts, Zod, Vitest.

**Deliverables:** runnable app, `README.md`, `DEMO_SCRIPT.md` (timed 2-min script + judge Q&A),
`.env.example`, `IMPLEMENTATION_SUMMARY.md`.

### Architecture decisions worth keeping

- `src/lib/simulation/` is **pure** — no React, no DOM, no network, no `Date.now()`. All four
  surfaces (Overview, Simulator, Community comparison, printable summary) call the same
  `runSimulation()` so their numbers cannot drift apart.
- Hydration-safe localStorage: deterministic defaults on first render → read in effect → writes
  gated on a `hydratedRef`. No hydration warnings.
- `src/lib/labels.ts` is dependency-free so client components don't pull seed data into the bundle.
- Replaceable `PolicyProvider` (`DemoPolicyProvider` + `createHttpPolicyProvider`); HTTP adapter
  activates only when both `POLICY_FEED_URL` and `POLICY_FEED_JURISDICTION_ID` are set server-side.
- Deep-partial `AssumptionOverrides` mapped type in `types.ts` — `Partial<T>` is shallow and
  rejects single-field scenario overrides.

### Defects the browser run caught (all fixed)

1. Two `<h1>` per page — `TopBar` rendered the page name as a heading. Now a `<p>`;
   `SectionHeading` gained a `level` prop so page sections own the single `h1`.
2. Unknown policy slug returned **HTTP 200** — `notFound()` after the shell flushes can't change
   the status. Fixed with `export const dynamicParams = false` on `/policies/[slug]`.
3. Bookmark button exposed only the generic name "Save policy". Added a policy-specific
   `aria-label` that *starts with* the visible text (label-in-name compliance).
4. Console 404 for `/favicon.ico` — `src/app/icon.svg` does not satisfy Chrome's direct
   `/favicon.ico` request. Generated a real 32×32 BMP-in-ICO at `src/app/favicon.ico`. Now 200.
5. Dashboard hint read "2 in effect or adopted · 1 proposed" under a tile whose value was 5.
   Reworded to "3 scenarios modelled · 2 binding · 1 proposed".

### Environment gotchas that cost real time

- **`http_proxy` is set in this environment** and intercepts `localhost`. Every local probe needs
  `curl --noproxy '*'` and `NO_PROXY="127.0.0.1,localhost"` for Node. The 502 it produced looked
  exactly like a stale/zombie server — it wasn't.
- **Background servers die when the parent shell exits.** Start the server, wait for readiness,
  run the browser script, and kill it — all in ONE shell invocation. Redirect output to a log
  file, never `| head` (closes stdout → SIGPIPE → server dies).

### Product constraints honoured (do not regress these)

- Unsupported locations **never** silently fall back to the demo city; the sidebar shows "Not
  covered" and the user is offered the demo as an explicit, labelled choice.
- Real policy rules vs hypothetical what-if settings are separated in types
  (`AssumptionNote.source`), in the UI (amber group badged "Does not change the policy"), and in
  the result — the policy's own rate stays visible when a what-if overrides it.
- No emissions / health / temperature / confidence-interval figures anywhere. Counts and weights
  stay separate because no conversion factor is documented.
- Demo contacts use reserved `.example` domains and 555 numbers so nothing is actionable.
- The email draft can be previewed, edited, and copied — there is no send path in the codebase.
